# 검색 필터 개선 계획 및 구현 결과

작성일: 2026-11-02 / UI 확정: 2026-11-03 (Asia/Seoul)
브랜치: `codex/search-filter-improvements`. develop 반영 전.

## 최종 UI

사용자 요청에 따라 검색창 오른쪽 아래 필터 버튼에 연결되는 **한 단계 팝오버 패널**을 사용한다.

- 진행 상태 6개는 두 줄의 버튼으로, 발의 기간과 정렬은 한 줄의 버튼으로 직접 고른다.
- 관심 법안만은 스위치, 소관 위원회는 같은 패널의 입력란으로 변경한다.
- 버튼과 스위치는 즉시 적용하고 패널을 유지한다. 위원회명은 입력 완료 또는 편집 종료 시 적용한다.
- 선택값은 배경·테두리와 접근성 selected trait로 표시한다.
- 초기화는 위원회를 포함한 모든 옵션을 지우고 검색어는 유지한다.
- 패널 밖을 누르면 닫힌다. 다시 열면 현재 조건을 표시한다.
- 시트, 중첩 메뉴, 별도 위원회 입력창과 적용/취소 단계는 사용하지 않는다.
- 기본 필터에서는 불필요한 조건 요약을 숨기고 변경된 조건만 요약한다.
- 작은 화면에서는 패널 높이를 제한하고 내용을 스크롤한다. 키보드 영역을 피하도록 구성한다.

## 검색 정확성

- 새 검색·필터 변경·검색어 편집/삭제마다 기존 요청을 취소하고 요청 세대를 갱신한다. 현재 세대의 응답만 UI·로딩·페이지·최근 검색어를 변경한다.
- API 원본 페이지의 전체 건수/크기와 필터 후 표시 결과를 분리한다. 필터 후 빈 페이지라도 뒤쪽 원본 페이지가 있으면 계속 탐색한다.
- 페이지 실패는 기존 결과를 유지하고 동일 페이지를 재시도한다. 중복 ID를 제거하고 누적 결과를 정렬한다.
- 캐시는 첫 페이지 대체에만 사용하고 저장된 결과라고 안내한다.
- 최근 N일은 오늘을 포함한 날짜 단위 범위로 계산한다.
- 제22대 법안명 검색과 응답 후 상태·위원회·기간·관심 필터링을 유지한다. 서버의 추가 검색/정렬 파라미터를 도입하지 않는다.
- 결과 수는 ‘불러온 N건’, 정렬 범위는 ‘불러온 결과 정렬’로 표시한다.

## 역할 분리

- SearchView: 검색창·결과 건수·조건 요약 및 필터 버튼 배치.
- SearchFilterViewController: 팝오버의 선택 UI와 즉시 변경 전달. 검색 요청은 소유하지 않는다.
- SearchViewController: 패널 표시 및 변경값을 ViewModel에 연결.
- SearchViewModel: 요청 세대·취소·페이지·검색 상태.
- Repository/API: 네트워크 페이지 메타데이터·캐시·응답 처리.
