## 바뀐 동작

| 문제 | 현재 동작 |
| --- | --- |
| 새 조건 요청이 기존 로딩에 막힘 | 새 검색 세대가 이전 요청을 취소하고 즉시 새 요청 시작 |
| 오래된 성공/오류가 새 결과·로딩·최근 검색어를 덮음 | 요청 당시 필터/페이지/세대를 캡처하고 현재 세대만 반영 |
| 검색어 삭제 후 결과 복원 | 편집/삭제 즉시 요청 취소와 결과 초기화, 늦은 응답 무시 |
| 필터 후 빈 페이지에서 검색 종료 | 원본 메타데이터/페이지 크기로 다음 페이지 판단, 빈 필터 페이지 뒤쪽 자동 탐색 |
| 페이지 실패 시 다음 페이지 건너뜀 | 마지막 성공 페이지 유지, 같은 페이지 재시도, 기존 결과 보존 |
| 캐시를 새 네트워크 페이지로 오인 | 첫 페이지만 캐시 대체, 저장된 결과 안내 |
| 초기화가 위원회를 누락 | 모든 옵션 초기화, 검색어 유지 |
| 시트 또는 중첩 메뉴로 선택 단계가 늘어남 | 검색창 아래 한 팝오버에서 상태·기간·정렬·관심·위원회 직접 변경 |
| 전체 결과처럼 보이는 건수 | 불러온 건수 및 불러온 결과 정렬 범위 표시 |
| 최근 N일 첫날 일부 제외 | 날짜 단위 양끝 포함 범위 |

SearchFilterViewController는 패널의 선택과 변경값만 담당한다. 검색 수명은 SearchViewModel, 원본 페이지와 캐시는 Repository/API가 담당한다.

- 첫 페이지 캐시 안내와 다음 페이지 캐시 반복 방지.
- 패널 선택 즉시 전달, 다른 조건·검색어 보존, 선택 trait, 위원회 입력과 전체 초기화.
- 검색 필터 버튼 및 패널 선택 버튼의 최소 44pt 높이, 288/340pt 패널 폭과 높이 제한.

## 범위와 한계

- 제22대 법안명 검색을 유지하며 나머지 조건은 응답 후 필터링한다. 최신/오래된순은 현재까지 불러온 법안의 정렬이다. 추가 페이지에 따라 순서가 바뀔 수 있다.
- 드문 조건은 여러 원본 페이지 요청이 필요할 수 있다. 조건 변경·검색어 편집 시 기존 탐색을 중단한다.
- 최종 패널 실물 검증은 iPhone 17 Pro 기본 글자 크기, 라이트·다크 모드, 하드웨어 키보드에서 진행했다. 실기기/iOS 16.4, 최종 패널의 소프트웨어 키보드·VoiceOver·최대 접근성 글자 크기·실제 iPad 화면은 별도 검증이 필요하다. 이전 시트 검증을 최종 패널 검증으로 간주하지 않는다.
- 위젯 갤러리 신규 추가와 데이터 조합의 실물 검증은 별도 후속 범위다. 이번 검색 작업에 위젯 소스를 변경하지 않았다.
