## 바뀐 동작

| 문제 | 현재 동작 |
| --- | --- |
| 새 조건 요청이 기존 로딩에 막힘 | 새 검색 세대가 이전 요청을 취소하고 즉시 새 요청 시작 |
| 오래된 성공/오류가 새 결과·로딩·최근 검색어를 덮음 | 요청 당시 필터/페이지/세대를 캡처하고 현재 세대만 반영 |
| 검색어 삭제 후 결과 복원 | 편집/삭제 즉시 요청 취소와 결과 초기화, 늦은 응답 무시 |
| 필터 후 빈 페이지에서 검색 종료 | 원본 API metadata/페이지 크기로 다음 페이지 판단, 결과가 없으면 자동으로 뒤쪽 탐색 |
| 페이지 로드 실패 시 다음 페이지 건너뜀 | 마지막 성공 페이지를 유지하고 실패한 페이지 재시도, 기존 결과 보존 |
| 캐시 결과를 새 네트워크 페이지로 오인 | 캐시는 첫 페이지 대체에만 사용하고 저장된 결과임을 안내 |
| 초기화가 위원회를 누락 | 모든 옵션을 기본값으로 되돌리고 검색어 유지 |
| 14개 액션의 즉시 적용 메뉴 | 5개 섹션의 전용 시트에서 draft 편집, 적용/취소/초기화 분리 |
| 긴 버튼 제목과 전체 결과처럼 보이는 건수 | 짧은 필터 버튼과 별도 조건 요약, 불러온 건수·불러온 결과 정렬 범위 표시 |
| 최근 N일 시작 날짜 일부 제외 | 날짜 단위의 양끝 포함 범위. 최근 30일은 오늘 포함 30개 날짜 |

View는 폼 배치, 필터 Controller는 draft 편집·적용, Search Controller는 표시와 연결, ViewModel은 요청 세대·검색 상태, Repository/API는 원본 페이지 및 캐시를 담당한다.

## 범위와 한계

- 기존 API의 제22대 법안명 검색을 유지한다. 상태·위원회·관심·기간은 응답 후 필터링한다. 서버 측 추가 검색/정렬 파라미터는 확장하지 않았다.
- 최신/오래된순은 **현재까지 불러온 법안**을 정렬한다. 서버 전체를 오래된순으로 조회했다고 표시하지 않는다. 다음 결과를 불러오면 순서가 바뀔 수 있음을 시트에 안내한다.
- 결과가 없는 원본 페이지를 자동 탐색하므로 매우 드문 조건은 여러 요청이 필요할 수 있다. 조건 변경/검색어 편집 시 진행 중 요청 및 뒤쪽 탐색을 중단한다.
- 실제 UI 검증은 iPhone 17 Pro의 기본 글자 크기와 하드웨어 키보드 입력으로 진행했다. 실기기/iOS 16.4, VoiceOver 읽기 순서, 최대 접근성 글자 크기, 소프트웨어 키보드 표시 상태와 실제 iPad 화면은 미검증이다. 창 크기 및 접근성 trait 자동 테스트가 이 실물 검증을 대체하지 않는다.
- 위젯 갤러리 신규 추가와 데이터 조합의 실물 검증은 별도 후속 범위다. PR #31의 검증 브랜치 기록은 유지하며 이번 검색 작업에 위젯 소스를 변경하지 않았다.
