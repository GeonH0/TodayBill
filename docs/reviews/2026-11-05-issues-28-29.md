# 즐겨찾기 갱신 실패와 검색 전체 개수 수정

대상 이슈: #28, #29. 병합 대상: develop.

## 변경

- 즐겨찾기 전용 `FavoritesViewState.cached`에 목록과 갱신 실패 안내를 함께 전달한다. 공통 `ViewState`의 다른 소비자에는 영향을 주지 않는다.
- 관심 법안 헤더의 기존 카드에서 저장된 정보이며 최신 상태가 아닐 수 있음을 알린다. 목록과 단계 변동 정보는 유지한다.
- 상세 화면에서 돌아오는 로컬 재조회도 실패 안내를 유지한다. 실제 갱신 성공 후 안내를 지운다. 캐시가 없으면 기존 오류 상태를 사용한다.
- API `list_total_count`를 서비스 → 저장소 → 검색 모델 → 화면으로 전달한다. 검색어만 적용한 페이지는 `전체 312건`처럼 표시한다.
- 상태·위원회·기간·즐겨찾기 필터는 클라이언트에서 적용하므로, 모든 페이지를 받기 전에는 `불러온 N건`, 마지막 페이지 이후에는 필터링한 전체 개수를 표시한다. 정렬 옵션만 바꾼 경우에는 API 전체 개수를 사용할 수 있다.
- 전체 개수 메타데이터가 없으면 불러온 개수를 표시한다. 오프라인 캐시는 `저장된 N건`으로 표시한다. 새 검색·필터 변경·삭제 시 이전 개수와 캐시 여부를 초기화한다.
- 기존 검색 개선 커밋 aee202c, 214f2dc를 함께 반영했다. 요청 취소·경합 방지·페이지 재시도·한 단계 필터 팝오버를 유지한다.

- API 전체 개수, 메타데이터 없음, no-data 0건 및 저장소 전달 테스트.
- 페이지 추가 후 전체 개수 유지, 새 검색 시 초기화, 로컬 필터에서 원본 전체 개수 숨김, 캐시 개수 구분 테스트.
- 즐겨찾기 실패 후 목록 유지, 로컬 재조회 시 안내 유지, 실제 갱신 성공 후 복구, 캐시 없는 오류 테스트.
